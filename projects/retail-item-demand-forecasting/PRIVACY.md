# Public-project data protection rules

This project ships **no genuine organisational data**, including pseudonymised or hashed actual store identifiers. It generates new, fictional store/item IDs and random demand values.

Before publishing any additions:
- Never upload genuine store IDs, reference mappings, POS transactions, internal forecasts, labour costs, colleague/customer information, screenshots of proprietary systems, credentials, API keys or internal SharePoint/Databricks paths.
- Do not upload source extracts simply because names or store numbers have been removed; transaction-level combinations and unusual values may still be identifying.
- Use synthetic inputs for examples, charts, sample outputs and tests.
- Review notebook outputs, git history, comments and file metadata as well as visible source code.
- Get appropriate employer permission before publishing actual derived internal results, proprietary business rules or system architecture.
- Label simulated results as simulated; do not present them as the original study's measured performance.
